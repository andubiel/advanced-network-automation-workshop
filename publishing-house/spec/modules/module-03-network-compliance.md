# Module 3: Network Compliance

### Brief Overview

This module teaches automated network compliance using Ansible resource modules with declarative state enforcement (state: replaced) and AAP workflows with human-in-the-loop approval nodes. Participants create workflow surveys, run compliance checks in check mode, interpret resource module output (unified diffs showing before/after state), approve remediation through AAP approval nodes, and validate the applied changes directly on network devices.

### Audience and Time

- **Target personas:** Network engineers responsible for compliance enforcement and configuration standardization
- **Prerequisites for this module:** Completion of Modules 1-2 (dynamic inventory and backup workflow operational)
- **Estimated duration:** 30 minutes

### Learning Objectives

- Implement network compliance checks using cisco.nxos resource modules with state: replaced to enforce declarative configuration
- Analyze resource module output including commands, before/after state, and unified diffs using ansible.utils.fact_diff
- Configure AAP approval workflows for human-in-the-loop compliance remediation

### Lab Structure

| Section | Title | Duration |
|---------|-------|----------|
| 1 | Create a workflow survey for compliance parameters | 5 min |
| 2 | Launch the compliance workflow in check mode | 5 min |
| 3 | Review compliance check output and unified diffs | 5 min |
| 4 | Examine the compliance playbook structure | 5 min |
| 5 | Approve remediation changes through the AAP approval node | 3 min |
| 6 | Review the remediation job output | 4 min |
| 7 | Validate remediation on a network device via SSH | 3 min |

### Detailed Steps

1. Navigate to the compliance workflow in AAP and create a survey to specify compliance parameters (e.g., logging and NTP settings)
2. Launch the compliance workflow which runs resource modules in check mode to detect configuration drift
3. Review the job output: examine the resource module return data including `commands` (what would change), `before` (current state), `after` (desired state), and `changed` status
4. Read the unified diff output generated by ansible.utils.fact_diff to see exactly what configuration lines differ
5. Examine the compliance playbook code: cisco.nxos.nxos_logging_global and cisco.nxos.nxos_ntp_global with state: replaced
6. When the workflow pauses at the approval node, review the proposed changes and approve the remediation
7. Monitor the remediation job execution and verify it applies the desired configuration
8. SSH to a network device (e.g., `ssh leaf3`) and run `show run | i logging` to confirm the compliance changes were applied

### Key Takeaways

- Resource modules with state: replaced enforce declarative compliance by replacing entire configuration sections to match desired state
- Check mode enables safe preview of compliance remediation before applying changes
- ansible.utils.fact_diff generates human-readable unified diffs for compliance review
- AAP approval nodes provide human-in-the-loop gates for change management workflows
- Compliance enforcement is idempotent -- re-running on compliant devices produces no changes

### Infrastructure Notes

- Network devices must have some configuration drift from the desired state for compliance checks to detect differences
- The compliance workflow requires pre-configured approval nodes in AAP
